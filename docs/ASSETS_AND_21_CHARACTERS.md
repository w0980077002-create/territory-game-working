# Приёмка ассетов: 3 папки / 21 новый персонаж

Владелец **сам загрузит три папки с изображениями 21 новых персонажей** в этот GitHub-репозиторий. **До загрузки ничего не выдумывать и не объявлять готовыми персонажами.**

## Ожидаемое от владельца
- Три папки с оригинальными файлами, с сохранением имён и иерархии. **Не требуется переименовывать их по предложенной исполнителем схеме** — Claude должен работать с фактическими именами загруженных папок.
- Главный утверждённый скриншот отдельно желательно поместить в `assets/references/main-screen-100-percent.png`; в разговоре был PNG 864×1536.
- Если для персонажа доступны PNG (прозрачный фон), WebP, кадры анимации и оригиналы, сохранять все варианты; не перезаписывать действующие арт-ресурсы.

## После загрузки: задача Claude
1. Найти все три папки, вывести точные пути и число файлов. Проверить содержимое и выявить 21 **различного** персонажа. Не принимать количество файлов за количество персонажей (один герой может иметь много файлов/кадров).
2. Составить таблицу `docs/CHARACTER_MANIFEST.md` для каждого из 21: название, роль (герой / враг / мини-босс / босс / спутник — по данным автора, не гадать), путь оригинала, PNG/WebP, размеры, alpha, наличие и формат кадров, состояния/анимации.
3. Для персонажей, чья роль не очевидна, пометить «роль уточняется». Не подставлять свою фантазию.
4. Использовать изображения для сцены главного экрана и игровых режимов. Не считать статичный WebP «живой анимацией». Реализовать реальные действия/состояния только на основе пригодных кадров, скелетной анимации или утверждённой программы анимации; показывать владельцу тестовую сцену.
5. Совместить с выбранными владельцем **собственными** элементами TERRITORY: фактурное старое тёмное дерево/золото/ковка, фоны/персонажи и Арена. Отбирать адресно, не тащить весь старый код и не трогать его сервер.
6. Сохранить самобытность/качество загруженного арта. **Запрещено заменить персонажа условной геометрией или чужим спрайтом**, а затем выдать за работу над этим героем.
