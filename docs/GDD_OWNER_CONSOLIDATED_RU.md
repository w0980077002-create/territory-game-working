## 1. Стек и архитектура
1. **Сборка:** TypeScript strict + Vite, SPA.
2. **Боевая сцена:** HTML5 Canvas / Phaser 3 (ориентир 60 FPS).
3. **Сложный RPG UI:** React 19 + Tailwind CSS + Lucide.
4. **Состояние:** Zustand, единый реактивный стор, данные сцены и UI согласованы.
5. **Сохранения:** Telegram.WebApp.CloudStorage; чанки JSON save_meta, save_equip, save_skills, save_talents (каждый до 4000 байт), автосохранение каждые 15 секунд и на visibilitychange; fallback localStorage для браузерной отладки. Для реальных наград, платёжных операций, рефералов и честного общего рейтинга потребуется валидация на сервере: клиентское сохранение само по себе нельзя считать доверенным.
6. **Мобильный экран:** 100vw × 100dvh, safe areas, Telegram WebView, отключение вертикальных жестов сворачивания, защита от закрытия.
7. **Десктоп:** центрированный портрет 480×854 px, оформление деревянным щитом.
8. **Структура:** src/core/telegram.ts; src/core/formulas.ts; src/core/types.ts; src/data/ (классы, навыки, руны, напарники, аффиксы, враги); src/game/ (боевой движок, частицы, отлеты, ProceduralArtFactory.ts); src/ui/ (RPG UI, инвентарь, лут-модалки, таланты). Формальная архитектура оформляется в ARCHITECTURE.md по отдельному заданию Claude.

## 2. Графика и анимация
**Базовая авторская стилистика из GDD:** европейский комикс 1960–1980-х (Астерикс/Обеликс как ориентир стилистики), гротескные пропорции, толстый тёмный ink-outline 3–4 px, яркая палитра, cel-shading, комиксные удары «БАМ!», «ХРЯСЬ!», «БДЫЩ!». Не сводить всю игру к плоским абстрактным прямоугольникам. Основной экран должен на 100% следовать изображению владельца (включая его насыщенность, большие красивые фоны, разделение сцены и экипировки).

**Процедурная фабрика:** Canvas 2D Path / SVG / Phaser Graphics; strokeStyle #1a1a1a, lineWidth=3, один слой теней. Использовать для вспомогательных элементов. Утверждённые владельцем изображения персонажей из трёх папок должны оставаться основным арт-источником, не заменять их процедурными простыми фигурами.

**Главный герой:** коренастый викинг либо высокий гигант по классу, большой круглый нос, крупные рыжие/жёлтые усы, крылатый металлический шлем; бумажная кукла (Paper Doll): смена шлема/оружия реально видна на персонаже. При беге squash & stretch, при атаке замах и motion-blur arc, при ульте золотое свечение.

**Римляне:**
- Легионер: красная туника, скутум, шлем с поперечным гребнем, комично длинный нос и испуганные глаза.
- «Черепаха»: три легионера в строю под щитами; 75% сопротивления обычному физическому урону, пока его не пробили навыком или критом.
- Пилумщик: худой римлянин с копьями, бросает по навесной траектории.
- Босс Центурион/Преторианец: массивный пузатый персонаж, золотая кираса, красный плащ, большой плюмаж.

**Game feel:** при смертельном ударе/крите враг отлетает по параболе и вращается; шлем/сандалии отлетают отдельно. При критах комиксная плашка на 0,4 с, camera.shake(120 мс, 0.008), hitstop 30 мс. Движение читаемое, камера не мешает UI.

## 3. Core loop и бой
- Стадии: Главы и уровни 1-1, 1-2, … 1-10, далее новые главы.
- Каждый уровень: **4 волны обычных врагов + пятая волна — босс**.
- Таймер босса — **30 секунд**.
- Смерть героя или истечение таймера: уровень не пройден, возвращение к текущему фарм-циклу/волне, бесконечный фарм золота и добычи перед повторной попыткой; кнопка «Бросить вызов Боссу».
- Герой и два спутника перемещаются слева направо, при контакте с врагом начинается авто-бой.
- Переключение скорости x1 / x2, x2 всегда бесплатно.
- **Рог Трофеев** — главная циклическая механика: заряды («Эль») регенерируют со временем/выпадают из врагов. Большая кнопка «ТРУБИТЬ В РОГ», удержание или Auto; по нажатию во время боя падает сундук и выдаёт добычу. Затрата заряда, выпадение и выбор результата должны быть реальными действиями, а не анимированной заглушкой.
- **Офлайн-награды — уточнение по новому исследованию:** первоначальное ТЗ предлагало золото/опыт/заряды Рога до 12 часов. В опубликованном гайде по оригинальной игре говорится об отсутствии стандартной idle-награды. До проверки актуального клиента не считать ни один вариант доказанным поведением Lootborn Warriors; исходную 12-часовую механику **не удалять молча**. Отразить расхождение в ARCHITECTURE.md и вынести на тест владельца. В реальной экономике не доверять времени клиента.

## 4. Формулы (не менять без разрешения)
**Основные характеристики:** HP, ATK, DEF, ASPD (удары/сек), CRIT_RATE, CRIT_DMG (база 150%), LIFESTEAL, DODGE, SKILL_DMG, DMG_REDUCTION.

```ts
Mitigation = DEF / (DEF + 100 + 15 * EnemyLevel)
RawDamage = ATK * SkillMultiplier * (1 - Mitigation)
if (Random() < CRIT_RATE) FinalDamage = RawDamage * CRIT_DMG
else FinalDamage = RawDamage
Heal = FinalDamage * LIFESTEAL

CP = Math.floor(
  HP * 0.2 + ATK * 2.5 + DEF * 1.8 +
  CRIT_RATE * 500 + CRIT_DMG * 200 +
  LIFESTEAL * 600 + DODGE * 500
)
EnemyHP = 120 * Math.pow(1.18, S)
BossHP = EnemyHP * 4.5
EnemyATK = 15 * Math.pow(1.15, S)
BossATK = EnemyATK * 1.8
GoldDrop = 10 * Math.pow(1.14, S)
```

**Важно при реализации:** в формуле CRIT_RATE и LIFESTEAL — доли [0, 1], CRIT_DMG = 1.5 для 150% (если UI отображает проценты, нормализовать до расчёта). ASPD, уклонение, DMG_REDUCTION, SkillDamage используются боевой логикой и проверяются тестами. S — сквозной номер стадии, а не отформатированная строка 12-5. Баланс значений проверить и показать владельцу, но не менять самовольно.

## 5. RPG системы

### 5.1 Предметы, инвентарь, кузница
- **12 основных предметов экипировки + отдельный 13-й предмет — крылья**: прямое уточнение владельца от 12.11.2026. Крылья надеваются **за спиной персонажа**, отображаются во время боя и дают **разные % бонусы к характеристикам**, с правильным пересчётом CP. Десять ранее записанных типов: Weapon, Helmet, Armor, Shield, Boots, Belt, Ring1, Ring2, Amulet, Cloak; названия **двух остальных основных слотов** следует подтвердить по интерфейсу Lootborn Warriors, не выдумывать. Подробности: [дополнение — раздел 1](LOOTBORN_FULL_SYSTEMS_APPROVED_20261112_RU.md).
- Уровень кузницы улучшается за золото; исходный GDD описывал повышение качества лута через Кузницу. **Благословение — дополнительная отдельная система**, которую нельзя сливать с Кузницей; актуальную формулу влияния обеих на дроп зафиксировать после сравнения с оригиналом.
- Шесть редкостей: Обычный (серый) → Необычный (зелёный) → Редкий (синий) → Эпический (фиолетовый) → Легендарный (оранжевый) → Мифический (красный).
- Новая вещь вызывает модальное сравнение: текущая/новая вещь, разница характеристик, изменение CP (+1420 зелёным или −310 красным), «Надеть» / «Распылить». Распыление даёт золото и опыт аккаунта.
- Auto-Salvage: автоматическое распыление вещей ниже заданного качества и с меньшим CP (в автоматическом режиме). Не распылять ошибочно ценные предметы, когда условие фильтра не выполняется.
- Paper Doll отражает смену реального оружия и шлема героя.

### 5.2 Классы — переключение в меню героя в любое время
- **Берсерк:** танк/вампир, +25% HP, +10% LIFESTEAL, два топора.
- **Следопыт:** крит/скорость, +15% CRIT_RATE, +20% ASPD, тяжёлый лук.
- **Рунолог:** AoE/магия, +30% SKILL_DMG, посох с молниями Тора.

### 5.3 Навыки и руны
**Три активных слота**, авто-каст по cooldown или ручная активация. По **одной руне на навык**, руна изменяет механику:
- Навык 1 «Сокрушительный Удар»: 220% урона одной цели, CD 6 с.
  - Огонь: ожог 4 с, каждый тик 50% ATK.
  - Гром: AoE по всем на экране, стан 1.5 с.
  - Пир: восстановление герою 20% Max HP при ударе.
- Навык 2 «Боевой Клич Одина»: +30% ATK на 5 с, CD 12 с.
  - Ярость: дополнительно +25% CRIT_RATE.
  - Каменная Кожа: +50% DEF и щит 15% HP.
  - Ускорение: сокращает CD остальных навыков на 2 с.
- Навык 3 «Молот Тора / Дождь Стрел»: 3 удара по 120% ATK, CD 10 с.
  - Пробитие: 100% игнор DEF врага.
  - Цепная Молния: каждый удар поражает 2 дополнительные цели.
  - Жадность: убийства дают +50% золота.
- Дубликаты навыков/рун объединяются для увеличения уровня (Merge).

### 5.4 Отряд — два активных напарника
- **Боевой Кабан Гром (танк):** забирает 40% урона врагов, пассивно +15% HP герою.
- **Друид Травник (поддержка):** лечение 15% HP раз в 7 секунд, пассивно +15% LIFESTEAL.
- **Карлик-Кузнец Брок (урон):** бросает раскалённые сковородки, оглушает; пассивно +20% CRIT_DMG.
- **Валькирия-Скаут (скорость):** арбалет по задним рядам, пассивно +15% ASPD.
Напарников призывают в лавке, затем прокачивают; они бегут и действуют в реальном бою.

### 5.5 Древо талантов
По одному очку на уровень аккаунта, сброс за золото:
- Ярость (красная) → ATK%, CRIT_RATE%, CRIT_DMG%.
- Стойкость (синяя) → HP%, DEF%, DODGE%.
- Удача (жёлтая) → Gold Drop%, шанс редкого лута из Рога, скидка Кузницы.

## 6. Telegram Mini App
- SDK: в исходном ТЗ указан `@twa-dev/sdk`. Проверить актуальную версию и поддерживаемые методы; официальный Telegram JS подключается с `https://telegram.org/js/telegram-web-app.js` в index.html.
- На старте: `WebApp.ready()`, `WebApp.expand()`, `WebApp.disableVerticalSwipes()` где поддерживается, `WebApp.enableClosingConfirmation()`; безопасный fallback вне Telegram.
- CloudStorage: логические save_meta/save_equip/save_skills/save_talents до 4000 байт/ключ, каждые 15 сек и visibilitychange; локальный fallback.
- Haptics: Рог/обычный лут `impactOccurred('medium')`; легендарная/мифическая вещь и победа над боссом `notificationOccurred('success')`; крит/ульта `impactOccurred('light')`; меню/прокачка `selectionChanged()`. Проверить поддержку/производительность, не вызывать на каждый кадр.
- В HUD имя Telegram: `WebApp.initDataUnsafe?.user?.first_name` для отображения, но для защищённых операций доверять только серверно проверенному initData.
- «Позвать Дружину»: Telegram startapp-реферал `ref_{userId}` и награда 50 зарядов Рога + 500 самоцветов по подтверждённому приглашению. Не выдавать награды за простое нажатие.
- Магазин Telegram Stars: интерфейс наборов самоцветов и `purchaseWithStars(itemId)`, в прототипе изолированные бесплатные тестовые покупки, в Telegram в дальнейшем `WebApp.openInvoice()`. Реальные покупки — только после отдельной серверной интеграции и подтверждения платежа.

## 7. Интерфейс (из GDD + утверждённого 100% скрина)
- Верхний HUD: слева аватар/имя/уровень/HP/CP; по центру глава/волны/скорость; справа валюты (золото, самоцветы, уровень кузницы), «Позвать Дружину».
- Главная сцена: герой, два спутника и враги, сильный многоплановый фон. Рог трофеев, три иконки активных навыков с радиальным КД, переключатель Auto. На референсной картинке компоновка плотнее, чем первоначальная концепция 45%/55%; **картинка важнее числового процента**.
- Боковые быстрые кнопки активностей; нижняя часть показывает реальную экипировку с уровнями и быстрыми действиями, нижняя навигация. Названия и точные позиции — по 100% скриншоту и дальнейшим решениям владельца.
- Пять предусмотренных GDD вкладок: **Герой** (Paper Doll, 12 основных предметов + крылья, класс, статы, кузница); **Навыки** (3 навыка, руны и Merge); **Отряд** (видимый бой/спутники, основной боевой и поддержка, звёзды/пробуждение; схема уточняется по оригиналу); **Таланты** (3 ветки); **Лавка** (призывы за золото/самоцветы и будущие Stars).
- **Арена TERRITORY:** сохранить проверенную механику как отдельный режим. «Подпольные бои» — обсуждаемый вариант названия, **пока не переименовывать**. Не переносить самовольно старую серверную реализацию. Режим и интерфейс интегрировать по отдельному плану.

## 8. Поручение Claude Code из первоначального GDD
1. Сначала создать **ARCHITECTURE.md**, описать структуру, схемы данных, формулы, поток боя, хранилище, UI и план интеграции. Представить для утверждения владельцем.
2. Не вырезать системы, описанные в GDD. Конечная игра должна иметь работающий код, а не TODO/заглушки. Реализация допускает последовательные завершённые игровые этапы без удаления конечного объёма.
3. После генерации выполнить npm install, npm run build и исправить TypeScript ошибки; проверять поведение, а не только сборку. Предусмотреть деплой независимого прототипа на Cloudflare Pages/Vercel или другой изолированный хостинг, не касаясь рабочего TERRITORY.

## 9. Требования из обсуждения после GDD
- **100% экран:** владелец назвал присланный скрин главного экрана не просто примером, а точным обязательным образцом; без самовольного редизайна.
- **Новые 21 персонаж:** владелец сам планирует загрузить **три папки** с арт-ресурсами. Исполнитель обязан изучить каждую папку и состав, сохранить оригиналы, реализовать персонажей по их ролям и анимациям, не путать с артом из старого репозитория. На 12.11.2026 три ZIP-части уже загружены владельцем в новый репозиторий; они побайтово идентичны проверенным ZIP частям из исходного проекта. После объединения и распаковки Claude обязан создать manifest и проверить персонажей.
- **Из старой TERRITORY:** особенно ценные составляющие — натуральное тёмное дерево, фоны/мир, свои персонажи, новая серия персонажей и действующая Арена. Копировать только выбранное и в новый проект; работающую игру и данные игроков не изменять.
- **Тестирование владельцем:** личная проверка на телефоне, затем он решает, что переименовать, удалить, скорректировать. Не принимать эти решения за него.
- **Скорость реализации:** приоритет видимой играемой версии, но не называть кликабельные заглушки готовыми системами. Чётко отмечать, что работает, а чего нет.
