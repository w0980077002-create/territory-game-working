# Банк идей из интервью — что делать позже

Версия реестра: **13.11.2026**. Все идеи относятся **только** к «Викингам и римлянам».

| Идея | Статус | Условие / оговорка |
|---|---|---|
| Живой городской раздел «Карты»: кузница с дымом, руны, склад, профессии, кликабельные здания | **Идея утверждена; очередь отдельно** | Не нарушать уже работающую кампанию и визуал |
| Живая анимированная Арена, видимые бои | **Желаемое направление; позже** | Не строить большой онлайн до завершения соло-игры |
| Кланы захватывают здания, получают ежедневные бонусы | **На потом** | Сложная онлайн/социальная механика |
| Интерактивные квесты с выбором «сила или хитрость» | **На потом** | Первый ежедневный квест — упрощённый |
| Альтернативные маршруты, ключи, поисковые загадки | **На потом** | Понравились, но не обязательны для первого варианта |
| Разные сюжетные исходы и награды (молот целый/повреждённый) | **Утверждён принцип, реализация позже** | При одинаковом исходе награда одинакова независимо от попыток |
| Ремонт повреждённого молота до сдачи | **Не утверждено** | Была идея помощника; требуется решение владельца |
| Ежедневные коды | **На потом** | Прямо отложено владельцем |
| Варьировать ежедневные задания и награды между днями | **Утверждено направление** | Конкретный календарь и таблица наград не определены |
| Общий сброс квестов по игровому времени без сервера | **Технический вопрос** | Согласован общий сброс; нужен надёжный источник времени, не доверять часам устройства |
| Баланс квеста с ориентиром ~95% успеха | **Цель** | Нужны тесты разных уровней, не выдумывать точную формулу |

## Что НЕ делать автоматически
- Не начинать одновременно все перечисленные системы.
- Не переделывать утверждённую игру с нуля и не создавать отдельную копию от Claude.
- Не менять правила наград так, чтобы проигрыши уменьшали приз.
- Не переименовывать новую игру «1.0».
- Не использовать эту папку для игровых идей старой «Территории».
- Не выдавать неутверждённую механику за принятую.

## Как пополнять после следующего интервью
Добавить запись с датой в отдельный `YYYY-MM-DD_INTERVIEW.md` **в этой же папке**; обновить оглавление `README.md` и этот реестр, если появились новые/переопределённые решения. Для каждого решения отмечать **кто и когда утвердил**, а если неизвестно — статус **«уточнить»**. Не заменять старое решение молча.
