## 1. Воссоздаваемый процесс «Царство тьмы» — ПРИОРИТЕТ P0
### 1.1 Вход и движение
`Город → Приключения → Тайное Царство Тёмной Энергии → список доступных этажей/Мучений → благословение → Вызов → ЖИВОЙ НЕПРЕРЫВНЫЙ БОЙ → выбор порталов на земле → новые биомы → финальный босс → итог → назад к этажам`.
- Н: архив 02, кадры 00:04, 00:12, 00:20, 00:24, 00:52, 00:56, 01:04; архив 03 описывает выбор пяти этажей, 3 слота благословения, стоимость входа в 1 единицу на видимой карточке, шкалу времени и счётчик 5/11, 9/11, 5/9. Восстановить эти переходы и визуальную иерархию, но **не** копировать цифровые цены/вероятности/арт без подтверждения правил.
- В: сначала **7 врагов** автоматически; затем **4 последовательных выбора** между **двумя порталами** непосредственно в боевой сцене; пройдён выбранный участок → опять два портала; после 4-го выбранного участка → финальный босс. Это уточнение владельца о механике конкурента; сам архив 02 показывает порталы, но один ролик не доказывает число всех вариантов и распределение случайности.
- В: каждый портал независимо получает **1, 2 или 3 звезды**. Варианты 1/3 и 1/1 допустимы — **не** подменять генератор алгоритмом «всегда один лёгкий, второй сложный» и не запрещать одинаковые предложения.
- В: 1 звезда → **9 врагов**, 2 → **10**, 3 → **11** на выбранном участке. Вынести числа в конфиг, покрыть тестами и сравнить с дополнительными кадрами, если будут; не считать их подтверждёнными покадровым протоколом 02.
- Н: биом меняется между отрезками — пустыня, тёмные руины, лес; герой и спутники движутся вправо, камера следует, портал стоит **на земле**, имеет подвижную внутреннюю магию, краткую подпись, не висит как UI-плитка.
- Не останавливать игру на промежуточном «VICTORY»/«Награда этажа». Переходы не требуют открытия меню. Пауза только по осознанному действию или скрытию приложения; при выборе портала бой ожидает на месте **без ошибки общего pause/resume**.

### 1.2 Результат, награда, сохранения
- В: после смерти финального босса одно итоговое окно **«Победа» + награды + «Забрать»**; при нажатии «Забрать» — атомарное получение награды и возврат к списку этажей. При поражении на любом участке — явное **«Поражение»** и кнопка возврата к этажам; не показывать старую победу при следующем старте этажа. Защитить от закрытия/повторного открытия модала.
- **Не смешивать** промежуточное накопление трофеев с итоговым подтверждением. Для новых заходов можно хранить pending/banked награду в run-state, но однократное итоговое начисление и правила поражения должны быть определены в одном месте, совместимом с действующей экономикой. Если видео не доказывает «всё теряется при поражении», НЕ выдавать это за правило конкурента.
- Пройденные этажи допускают повтор; следующий этаж открывается только после финального босса; победа на повторном этаже не сбрасывает максимальную глубину. Результат `win/lose`, состояние `unclaimed/claimed`, выбранные порталы, остаток врагов, текущий участок и выданные награды переживают reload/background. Потеря localStorage/CloudStorage, двойной tap и два открытых окна не дублируют награды. Legacy save из 3-комнатной версии мигрировать **без вайпа** и без повторного списания входа. На незавершённой старой попытке нужен документированный безопасный путь восстановления/продолжения.
- Переход на новый этаж — **после** получения результата, не до; не спавнить новый бой за спиной итогового окна. Не показывать итог предыдущего этажа на входе в следующий.

### 1.3 Конечный автомат (реализовать явно)
`IDLE → ENTRY_PAID → INTRO_7 → CHOICE_1 → SEGMENT_1 → CHOICE_2 → SEGMENT_2 → CHOICE_3 → SEGMENT_3 → CHOICE_4 → SEGMENT_4 → FINAL_BOSS → RESULT_WIN_PENDING → CLAIMED → FLOOR_SELECT`.
Переход `INTRO/SEGMENT/BOSS → RESULT_DEFEAT → FLOOR_SELECT`. `CHOICE` хранит **уже сгенерированную** пару звёзд и id выбора (не перегенерировать при rerender/reload); `SEGMENT` хранит общее и оставшееся количество врагов, `phase`/wave/checkpoint. Каждое событие устойчиво к повторному вызову; учёт уникального `runId`/`resultId`.
