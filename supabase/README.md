# Общий контракт VVR на W066

- Идентичность игрока хранится в существующей `vvr.players`. После проверки Telegram initData функция `vvr.resolve_player(telegram_id, display_name)` возвращает постоянный UUID. Для Edge Functions общая проверка и формат сессии находятся в `functions/_shared/vvr-identity.ts`. Формат сессии использует `VVR_SESSION_SECRET` проекта и UUID игрока. Оба Edge-обработчика проверяют подпись через одну функцию и используют проектный `TELEGRAM_BOT_TOKEN`.
- Доверенный обработчик передаёт этот UUID в `vvr.issue_resource(player, kind, event, currency, amount)` и `vvr.issue_item(player, kind, event, catalog_id)`. Повтор события возвращает прежний результат. Для каждой строки награды нужен собственный стабильный UUID события. Числа и каталог определяет серверный обработчик босса. `vvr.resource_receipts` остаётся журналом начислений и пополняет общий `vvr.wallets` в той же транзакции.
- Для рейтинга проверенный итог боя записывается через `vvr.record_score(player, metric, event, points, occurred_at)`. Метрики первой версии — `world_boss_damage` и `arena_wins`. Повтор использует исходное серверное время и тот же UUID. Границы сезона заданы в `vvr.seasons`, начало включено, конец исключён.
- Выдача ресурсов и предметов доступна роли `vvr_reward_writer`, запись результатов — `vvr_score_writer`. Обработчик может вызвать обе операции в одной транзакции. Edge-посредник аукциона и чата использует только RPC для сессии и действий игрока. Снимки Solo остаются копиями сохранений.

Для локальной проверки схемы и конкурентной покупки используйте `bash scripts/qa/w066-postgres.sh`. Сборка GitHub Pages использует публичные URL отдельного W066. Права на операции и ключи проекта хранятся на сервере. В W066 Edge Functions читают `TELEGRAM_BOT_TOKEN` и `VVR_SESSION_SECRET` из Supabase Vault. Локальная проверка использует одноимённые переменные окружения.

Миграция `20261124155543_vvr_world_boss_community.sql` применяется после #101. Она направляет подтверждённый урон в сезонный рейтинг и использует прежние квитанции для пополнения общего кошелька. Урон берётся из настроек боя и умножается на доверенную силу атаки относительно базовых 100, с пределами 0,5 и 2. Пока у героя нет серверной ревизии, действует базовый урон. Только роль `vvr_hero_writer` может публиковать ревизии через `vvr.set_hero_attack(uuid, revision, attack_power)`. Локальные снимки Solo в расчёт не входят.

Публичные URL сборки Pages можно переопределить переменными `VVR_COMMUNITY_URL` и `VVR_WORLD_BOSS_URL`. Для босса разрешённый origin задаётся в `WORLD_BOSS_ALLOWED_ORIGINS`, для сообщества при необходимости в `VVR_WEB_ORIGIN`.

Для резервной копии Solo используется отдельный маршрут `vvr-community/backup` с той же Telegram-сессией. Клиент открывает текущую ревизию перед записью. Запись с устаревшей ревизией отклоняется, а предыдущую копию можно прочитать. Импорт Solo не начисляет сетевое золото и не меняет экипировку.

Серверный клинок выдаётся при получении письма за последний удар мирового босса. Он участвует в аукционе и добавляет 10 к силе атаки при экипировке. Текущего владельца и отсутствие открытого лота проверяет PostgreSQL.

На существующем сервисе Арены `VVR_ARENA_SCORE_URL` указывает на `vvr-community/arena-result`, а `VVR_ARENA_SCORE_TOKEN` хранит отдельный серверный ключ (64 hex-символа). В W066 хранится только его хеш. SQLite сохраняет очередь отправки на основе журнала завершённых боёв, победы над ботами не публикуются.

Приглашение учитывается при первой регистрации в W066 с подписанным параметром Telegram `start_param=ref_<uuid пригласившего>`. Последующие входы сохраняют исходную привязку. RPC списка читает подтверждения только для владельца сессии; статус начисления берётся из `vvr.resource_receipts`. Внутренняя `vvr.issue_referral_reward` использует UUID приглашённого как идентификатор события, доступна только владельцу функции и не вызывается приложением. Для запуска начислений требуется отдельная утверждённая серверная политика.
