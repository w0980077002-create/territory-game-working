# VIKING VS ROME: LOOTBORN SAGA — ЕДИНАЯ ТОЧКА ВХОДА

**Проект:** отдельная Telegram Mini App-игра. **Статус на 12.11.2026:** подготовлены требования и арт, игровой код ещё не создан, Claude Code не начинал работу. Это **полный проект**, а не поручение выпустить урезанную версию. Реализация может проверяться этапами, но утверждённые функции не удаляются из итогового объёма.

## 1. Цель, которую утвердил владелец

Сделать **максимально полный по игровым механикам, экранам, развитию, режимам, экономике и игровому ощущению аналог Lootborn Warriors**. Использовать утверждённый владельцем главный экран **«100%»** как обязательный визуальный результат. При этом встроить собственных 21 персонажа, выбранное оформление, фоны и работающие элементы игры TERRITORY. Когда появится настоящая работающая версия, **владелец сам проверит её в Telegram и решит, что изменить или переименовать**. Нельзя подменить задачу упрощённой idle-игрой «по мотивам».

**Правило №1:** если владелец утвердил картинку словами «так должно быть 100%», её композиция, плотность, пропорции, расположение кнопок, стиль и содержание считаются **обязательными**. Не менять без согласования. Адаптация под разные экраны не должна упрощать или прятать ключевые элементы.

**Отдельно утверждено владельцем 12.11.2026:** большая **центральная шестиугольная кнопка с перекрещёнными топорами ОСТАЁТСЯ именно как на PNG** — прежнее место, форма, изображение и размер. **Не заменять её Рогом Трофеев, не менять значок и не добавлять вместо неё другую центральную кнопку.** Механика Рога, если реализуется, размещается без изменения этой кнопки и других элементов эталона; неизвестное действие центра не выдумывать.

**Файл эталона реально находится здесь:** [assets/references/main-screen-100-percent.png](assets/references/main-screen-100-percent.png), **864×1536 PNG**. Это **само изображение**, не только его текстовое описание. Дополнительная [карта зон](docs/SCREEN_PIXEL_MAP_100_PERCENT_864x1536_RU.md) является вспомогательной и не отменяет PNG.

## 2. Утверждено владельцем — без повторного спора

- **12 основных слотов экипировки + отдельная 13-я вещь «Крылья»**. Крылья надеваются за спиной и дают разные **процентные** бонусы к характеристикам; смена отображается в живой сцене, пересчитывает статы/CP.
- **21 собственный персонаж**: 3 героя, 2 спутника, 8 обычных врагов, 3 мини-босса, 4 босса, 1 особый. Проверенные PNG и WebP уже извлечены; WebP — только стоп-кадры, **готовых анимаций пока нет**. [Реестр](docs/CHARACTER_MANIFEST.md) · [отчёт импорта](assets/characters/v2-source/EXTRACTION_REPORT.json).
- Реальные бой, враги, движение, взаимодействия, добыча, прокачка, навыки, арена и все найденные системы Lootborn; никакого «готово» лишь по статичным картинкам или успешному CI.
- Из TERRITORY выборочно берём собственный визуал, фактурное натуральное дерево, согласованные персонажи и режим Арены; **живую TERRITORY, её Telegram-бота, Supabase, кошельки, VIP и прогресс игроков не изменяем**.
- **Визуальный экран важнее приблизительных процентов** 45% Canvas / 55% UI и разработческих предпочтений, записанных ранее.
- Пользователь хочет **всё до мелочей**: эффекты, цены и наборы тоже должны быть исследованы и учтены; неверно установленные цифры **не выдавать за оригинальные**.

## 4. Состояние репозитория: что ЕСТЬ и чего НЕТ

**Есть:** сам утверждённый PNG, извлечённые 21 PNG-мастер/21 WebP-превью/10 оригиналов, манифест, 3 транспортных ZIP для происхождения, документы и импортный GitHub Actions. Проверка архивов в GitHub Actions ранее прошла успешно.

**Нет:** `package.json`, `src/`, живой боевой сцены, анимаций, тестовой сборки, прогресс-сервера, тестового Telegram URL, CI сборки игры и проверок на физическом телефоне. **Игру не считать реализованной.**

Временное дублирование трёх транспортных ZIP и распакованных мастеров сохраняется **для сохранности исходников** до решения владельца об удалении архивной копии; производственная сборка не должна включать ZIP и PNG-мастера целиком, только оптимизированные игровые ресурсы.

## 5. Что должен сделать Claude при получении команды

1. Прочитать этот файл, [CLAUDE.md](CLAUDE.md), актуальный GDD, [решения/расхождения](docs/DECISIONS_AND_GAPS.md), [план](docs/IMPLEMENTATION_PLAN.md) и [поручение](docs/WORK_ORDER_FOR_CLAUDE.md).
2. **Сначала быстро подготовить ARCHITECTURE.md**: стек, игровые данные, сцена, state machine, формулы, модули, тестовый деплой, сохранения и контроль изменений. Это **внутренний технический план Claude, не этап утверждения владельцем**. Создать, сохранить в GitHub и продолжить разработку самостоятельно.
3. **Сразу после создания архитектуры, без ожидания разрешения**, делать живую игру по этапам с отдельным тестовым URL. **Первый тест** — точный главный экран, реальный бой/волны/босс, герой и спутники, лут/экипировка, 12+крылья, Auto/x2, save/reload. Все остальные 201 пункт остаются в обязательном scope последующих этапов.
4. Проверять результаты на Android/Telegram WebView, не называть сборку «готовой» до фактического игрового теста. Исключить любые записи в продакшен TERRITORY.

**Владелец утверждает игровой результат на телефоне, а не схему модулей/файлов.** Переделка утверждённого экрана, изменение концепции, баланса, экономики, цен или платежей требуют его явного согласия; обычные технические решения Claude принимает самостоятельно. **Неизвестные точные цены, шансы, составы пакетов и два названия основных слотов не додумывать:** фиксировать `UNVERIFIED` и запрашивать подтверждение **только для конкретных блокирующих решений**. Для архитектуры предусмотреть конфигурацию, а не выдуманные «официальные» числа.
