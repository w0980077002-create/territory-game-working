# VIKING VS ROME — карта действующего кода
Справочник архитектуры, не очередь задач. Описание клиентского кода ниже основано на состоянии 19.11.2026; сверять изменяемый модуль с актуальным кодом. Текущая очередь — Issue #81.

- React, TypeScript, Vite, Zustand, Canvas 2D. Одна игровая ветка codex-build, одна Pages-ссылка.
- src/core — состояние героя, добыча, экипировка, транзакции и сохранения. Локальный и Telegram CloudStorage; совместимость существующих сейвов, резервные банки и однократная выдача наград обязательны. Клиентский Solo не является доверенной серверной экономикой.
- src/data и config — каталоги, персонажи, игровые параметры, 12 основных слотов и отдельные крылья. Временные значения не выдавать за оригинальные. Не изменять утверждённую экономику самовольно.
- src/game — живой бой, перемещение, отрисовка, AI, волны, боссы, поражение и повторы. Центральные топоры START/PAUSE/RESUME, Auto и x1/x2 — утверждённая композиция.
- src/ui — окна и HUD; компактная вертикальная компоновка, отдельный слой крыльев, действия через core. Не создавать вторую реализацию механик в UI.
- src/dark/realm.ts — Царство тьмы: вступление из 7 врагов, четыре выбора пары порталов и четыре участка, затем финальный босс. В текущем коде портал содержит count 9/10/11 и stars из 1/2/3/4; это описание факта, не новое решение о сложности или балансе. Маршрут в RealmRun; награда накапливается и выдаётся при подтверждении результата. Остальные тёмные системы — rules/actions и окна DarkPanels.
- Карнавал: интеграция UI и логики в PR #58; задания и награды используют действующее состояние игрока и сохранения. Не переносить тестовые данные стенда в игру.
- Публикация: существующий GitHub Actions → GitHub Pages, без main и TERRITORY. Автоматические проверки плюс фактическая приёмка в Telegram Android.

Исторические планы и 201 пункт исследований — справочники, не обязательства текущего релиза. Реальные платежи требуют отдельного решения владельца. Не выдавать описания или симуляции за работающие сетевые функции.

## Утверждённая серверная архитектура
Цель: GitHub Pages + отдельный Supabase W066. Railway/SQLite сохранять для работающей Арены до проверенной замены. Общая экономика — доверенные транзакции PostgreSQL W066; не доверять клиентским Solo-статам для ranked. Переиспользовать подходящие решения TERRITORY и части #94 без автоматического слияния всего PR. Перенос Арены на RPC оценивать по паритету, нагрузке, сохранности и восстановлению; отключать Railway только после проверенной замены. Единый контракт идентификации и начислений, без параллельных кошельков, профилей или журналов. При отсутствии доступа или контракта — изолированный модуль и тесты без применения к живой базе. Фактическое состояние деплоя проверять по текущему SHA и Issue #81, не по историческим описаниям.
