# Инженерный процесс VVR

1. Брать один независимый пакет из [Issue #81](https://github.com/w0980077002-create/territory-game-working/issues/81); сверять затронутый код и [архитектуру](ARCHITECTURE.md). Использовать существующие Skills и доказательства. Полный аудит только при обоснованной необходимости.
2. Проверять изменённую логику, зависимости, сохранения, защиту от дублей; при UI-изменениях — 320/360/390/430 px. Для Арены — два независимых автоматизированных клиента и один игрок против бота, очередь, Auto, эликсиры, исход, восстановление, однократные награды. Физическая Telegram Android приёмка отдельно; её отсутствие не блокирует независимую разработку.
3. Проверять CI на актуальном SHA, объединять проверенные изменения в codex-build; проверять фактический deploy и health затронутых сервисов. Не обходить CI. Перед повтором миграции, деплоя или merge проверять фактический результат.
4. Раздельные ветки исполнителей, согласованная интеграция общих файлов. Распределение задач только в Issue #81. Внешние блокеры не останавливают независимые пакеты.
5. Глубина рассуждений при наличии настройки: Medium — простой UI, High — механики, High/Extra High — экономика и безопасность, Extra High — критические ошибки. Дорогие ускоренные режимы только при необходимости.
6. После пакета фиксировать ветку, SHA, PR, CI, деплой, оставшиеся шаги и блокеры; владельцу краткий результат и ссылку. При остановке продолжать с подтверждённого состояния, новый чат — с компактной сводкой. Не повторять завершённые проверки без причины.
