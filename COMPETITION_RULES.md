# Параллельная разработка: Claude Code против Codex

**Решение владельца:** оба исполнителя самостоятельно создают полную игру VIKING VS ROME: LOOTBORN SAGA по **одному утверждённому ТЗ** и одинаковому исходному состоянию. Сравнивается **реальная работающая игра на телефоне**, не длина отчёта и не число коммитов.

## Строгое разделение

- **Claude Code**: работает только в ветке `claude-build`. Не коммитить и не мержить в `main` или `codex-build`.
- **Codex**: работает только в ветке `codex-build`. Не коммитить и не мержить в `main` или `claude-build`.
- Ветки создаются владельцем/партнёром из **одного и того же commit SHA**. **Не подтягивать код конкурента**, не копировать PR/коммиты из его ветки, не синхронизировать ветки без явного решения владельца.
- Общие материалы для обоих: `CLAUDE.md`, `PROJECT_BRIEF.md`, GDD, 201 контрольный пункт, утверждённый экран `assets/references/main-screen-100-percent.png`, реестр 21 персонажа, `config/test-balance.v1.json`.
- Каждый исполнитель обязан создавать собственный **постоянный HTTPS-адрес тестовой игры**, отличный от адреса конкурента, с безопасным автообновлением именно своей ветки. Нельзя направлять обе ветки на один production-деплой, базу или общие изменяемые ресурсы. Если хостинг пока не доступен, ясно обозначить проблему, продолжать разработку и запросить одно конкретное действие по выдаче доступа.
- В каждом проекте **отдельные тестовые сохранения и изолированная экономика**, без связи с рабочей TERRITORY и без настоящих платежей/Stars.
- Каждый создаёт и поддерживает собственный PR в `main` **без слияния** до выбора владельцем; изменения публикуются в ветку исполнителя. Статус «готово» допустим только после реального игрового теста.
- Не включать автоматический merge или продакшен-релиз. Владелец может выбрать одного исполнителя либо объединить лучшие решения **после независимого сравнения**, с тестами конфликтов и разрешением владельца.

## Как сравнивать на равных

**Одинаковая первая контрольная точка:** утверждённый главный экран 100%, собственные герои/спутники/враги/мини-боссы/боссы, настоящие анимации и AI, волны, реальный лут, 12 вещей + отдельные крылья, сохранение, кнопки, Auto/x2, мобильный интерфейс. После неё продолжать **весь** заявленный игровой объём; не урезать ТЗ ради соревнования.

При отчёте предоставить:
1. URL своей живой версии для Android (указать отдельно проверен ли Telegram WebView).
2. Commit SHA, PR, список реально работающих действий, скрин сравнения с эталоном и запись боя.
3. Проверку сохранений, наград, экономики, производительности, обработки ошибок; честный список того, что ещё НЕ готово.

**Итоговое сравнение:** точность дизайна, живость/красота, настоящая игровая механика, отсутствие дублирования наград и потери прогресса, удобство Android/Telegram, техническая поддерживаемость и прогресс остальных систем.

## Безопасность

Репозиторий приватный; сам факт существования веток **не устанавливает GitHub branch protection**. Исполнитель обязан соблюдать ограничение независимо от своей роли. Не менять `main`, рабочую TERRITORY, бота, prod Supabase, VIP, кошельки и игроков.
